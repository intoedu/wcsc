# CAPS 교회지원센터 홈페이지 + 관리자 시스템

**CAPS** (Church Assist Platform Service) — 한국 교회를 위한 통합 지원 기관 홈페이지.
8개 지원 항목 안내, 온라인 신청, 그리고 **로그인 기반 관리자 시스템**을 포함합니다.

- 홈페이지 내용은 **로그인 없이 누구나** 볼 수 있습니다.
- 신청서 제출과 관리자 화면은 **로그인**이 필요합니다.
- 데이터베이스는 **Firebase** (Firestore + Authentication) 를 사용합니다.
- 설정이 비어 있으면 **로컬 데모 모드**로 동작하므로, 설정 없이도 전체 기능을 바로 확인할 수 있습니다.

## 1. 현재 연결 상태

**Firebase 프로젝트 `caps-4e079` 에 연결되어 있습니다.** (`assets/js/firebase-config.js`)

```bash
npm start     # http://localhost:8123
```

실제 데이터가 Firestore에 저장되므로, 로컬에서 테스트한 내용도 운영 데이터에 그대로 들어갑니다.
테스트로 만든 신청·고객은 관리자 화면에서 삭제하세요.

이 모드에서는 예시 데이터와 함께 아래 계정으로 로그인해 화면을 둘러볼 수 있습니다.

## 3. 진입점 — 고객과 직원이 분리되어 있습니다

| 대상 | 진입점 | 하는 일 |
|------|--------|---------|
| **교회 (고객)** | `index.html` 헤더 [로그인] | 지원 신청, 내 신청 조회. 직원 관련 항목은 보이지 않습니다 |
| **센터 직원** | **`staff.html`** | 직원 전용 로그인 · 계정 신청 → 승인되면 `admin.html` 로 자동 이동 |

직원 포털(`staff.html`)은 공개 홈페이지 메뉴에 노출하지 않습니다. 찾아가는 경로는 두 가지입니다.

- 푸터 **센터 안내 → 직원 로그인**
- 홈페이지 로그인 창 하단 **"CAPS 센터 직원이신가요?"**

### 서로 이동

- 관리자 화면 → 사이드바 맨 아래 **홈페이지 보기**
- 홈페이지 → 로그인한 직원의 사용자 메뉴에 **관리자 화면**
- 직원 포털의 모든 안내 화면에 **홈페이지로 이동** 버튼

### 직원 포털의 로그인 결과별 화면

| 계정 상태 | 화면 |
|-----------|------|
| 승인된 직원 (최고관리자·관리자·직원) | 업무 시스템으로 자동 이동 |
| 승인 대기 직원 | "승인을 기다리고 있습니다" + [승인 확인] 버튼 |
| 고객 계정 | "직원 계정이 아닙니다" + 홈페이지 · 내 신청 내역 안내 |
| 연결 실패 | 원인 안내 + [다시 시도] |

> `staff.html` 에서 하는 회원가입은 **항상 직원 신청**(승인 대기)입니다.
> 홈페이지에서 하는 회원가입은 **항상 고객**입니다. 스스로 직원이 될 수는 없습니다.

### 추가 정보 입력 — 교회명 · 직분 · 연락처는 필수

구글 계정으로 가입하면 이름과 이메일만 넘어옵니다. 그래서 **로그인할 때마다**
교회명 · 직분 · 연락처가 채워져 있는지 확인하고, 비어 있으면 **닫을 수 없는
[추가 정보 입력] 화면**으로 막습니다 (`assets/js/profile.js`).

- **구글 가입 버튼이 회원가입 창 맨 위**에 있습니다 (홈페이지 · 직원 포털 모두).
  아래 입력칸을 비워둔 채 눌러도 되고, 인증 뒤 이 화면에서 받습니다
- 이메일 가입은 지금처럼 폼에서 한 번에 받습니다 (이 화면이 뜨지 않습니다)
- 예전에 만들어진 계정도 다음 로그인 때 이 화면을 거칩니다
- 공개 홈페이지 · 신청 폼 · 직원 포털 · 관리자 화면 **모두** 같은 지점에서 막힙니다
- 배경 클릭 · Esc · 닫기 버튼으로 넘어갈 수 없고, **로그아웃**만 가능합니다
- 저장하면 원래 하려던 동작(신청서 제출, 관리자 화면 진입 등)으로 그대로 이어집니다

> 이 기능은 보안 규칙을 바꾸지 않습니다. 본인 계정의 이름 · 연락처 · 교회 ·
> 직분 수정은 이미 허용되어 있습니다 (직분/승인/권한은 바뀌지 않기 때문입니다).

### 4-1. 지원 항목 수정 → 홈페이지 즉시 반영

관리자 화면 → **지원 항목** → 항목별 [수정] 에서 아래를 고칠 수 있습니다.

- 항목 이름, 한 줄 소개, 요약 설명, 소요 기간, 비용 안내
- **지원 내용** (제목 + 설명, 추가/삭제/순서 편집)
- **제공 내역** (목록)
- **자주 묻는 질문** (질문 + 답변)
- **공개 여부** — 끄면 신청 버튼이 막히고 "접수 일시 중지" 안내로 대체됩니다. 페이지 주소는 유지됩니다.

**외부 접수 항목** — `외부 접수 주소` 를 넣으면 그 항목의 신청이 다른 사이트로 연결됩니다.
현재 **홈페이지 제작 · 디자인 제작** 은 @IM 접수 페이지(`koreayjk.github.io/aim/request.html`)로 연결되어 있습니다.

- 항목 상세 페이지의 버튼이 `@IM에서 신청하기` 로 바뀌고 새 창으로 열립니다
- CAPS 신청서에서는 체크박스가 아니라 **링크 카드**로 표시됩니다 (선택 불가)
- 주소를 비우면 다시 CAPS 신청서로 접수합니다

동작 방식은 다음과 같습니다.

1. 정적 HTML(빌드 결과)이 **기본값**으로 먼저 표시됩니다 → 검색 노출과 초기 로딩에 유리
2. `assets/js/live-content.js` 가 관리자 수정본을 가져와 **덮어씁니다**
3. 데이터를 못 가져와도 페이지는 기본 내용으로 정상 동작합니다

수정하지 않은 항목은 기본 내용이 그대로 나갑니다. [기본값으로 되돌리기] 로 언제든 원복됩니다.

> 항목을 **새로 추가**하거나 **순서를 바꾸는 것**은 `src/data/site.js` 를 고친 뒤 `npm run build` 를 실행해야 합니다.
> (항목 개수는 메뉴·목록·비교표 등 여러 곳의 정적 구조와 맞물려 있습니다.)

### 4-2. 작업 관리 (내 작업 · 전체 작업 · 업무량)

**전체 작업**은 권한 없이 모든 직원이 볼 수 있습니다. 누가 무엇을 언제까지 하는지 서로 알 수 있도록 열어둔 화면이며, 수정은 되지 않습니다.

**내 작업**에서는 자기에게 배정된 건만 보이고, 여기서 **마감일(디데이)** 을 직접 설정합니다.
표에서 날짜를 고르면 바로 저장되고 디데이 배지가 갱신됩니다.

| 배지 | 뜻 |
|------|-----|
| `D-7` `D-2` | 남은 일수 (3일 이내면 주황색) |
| `D-DAY` | 오늘 마감 |
| `D+3` | **3일 지남 (지연)** — 빨간색 |
| `미설정` | 마감일을 정하지 않음 |
| `완료` | 완료·취소된 건 (지연 계산 제외) |

**직원별 업무량**은 직원 관리 권한자(최고관리자 포함)만 볼 수 있습니다. 진행 중 건수를 막대로 비교하고, 지연·3일 이내·마감 미설정 건수를 함께 보여줍니다. 담당자가 정해지지 않은 건도 알려줍니다.

> 담당자로 배정된 직원은 `신청·의뢰 관리` 권한이 없어도 **자기 작업의 마감일·상태·메모·할 일만** 수정할 수 있습니다. 담당자 재배정은 권한자만 가능하며, 이 제한은 `firestore.rules` 에서 서버측으로 강제됩니다.

### 4-3. 고객 계정 관리

**관리자 목록 → 고객 계정** 탭에서 가입자 정보를 확인합니다.

| 열 | 내용 |
|----|------|
| 이름 · 이메일 · 연락처 | 가입 시 입력값 |
| **교회** · **직분** | 가입 시 필수로 받습니다 |
| **생년월일** | 가입 시 선택 입력 |
| 가입일 | — |
| **⋯** | 직원으로 전환 / 계정 정보 삭제 |

- **직원으로 전환** — 고객을 직원(승인 완료) 으로 바꾸고 승인된 직원 탭으로 이동합니다. 전환 후 권한 체크박스에서 필요한 항목을 켜주세요.
- **계정 정보 삭제** — `users` 문서를 지웁니다. 그 사람이 남긴 신청 내역은 남습니다.

> ⚠️ 계정 정보를 삭제해도 **로그인 계정 자체는 남습니다.** 브라우저에서 남의 로그인 계정을 지우는 것은 보안상 불가능하기 때문입니다.
> 완전히 지우려면 Firebase 콘솔 **Authentication → Users** 에서도 삭제해 주세요. 지우지 않으면 그 사람이 다시 로그인할 때 고객으로 새로 등록됩니다.

### 4-4. 교회 정보 수정은 그 교회의 승인을 받습니다

교회가 알려준 정보를 센터가 임의로 고칠 수 없게 막아 두었습니다.
**요청 → 고객 승인 → 수정 → 자동 재잠금** 순서로 진행됩니다.

```
관리자: 고객 관리 → 교회 열기 → [정보 수정 요청 보내기]
          ↓  (고칠 항목 선택 + 사유 입력)
고객:  홈페이지 접속 → 안내 띠 · 승인 창 → [승인합니다] / [거절합니다]
          ↓
관리자: 고객 관리 → 잠금 해제 (7일) → 수정 후 [저장] → 다시 잠김
```

**승인이 필요한 항목** (교회가 알려준 정보)

| 항목 | 항목 |
|------|------|
| 교회명 | 담당자 성함 |
| 교단 | 담당자 직분 |
| 소재지 | 연락처 |
| 출석 교인 수 | 이메일 |

**승인 없이 언제든 수정되는 것** — 내부 메모, 구독 계약, 청구·정산, 신청 상태·담당자·마감일

고객 쪽 화면
- 요청이 있으면 홈페이지 헤더 아래에 **안내 띠**가 뜹니다 (모든 공개 페이지)
- 로그인 후 승인 창이 한 번 자동으로 열립니다. **닫을 수 있고**, 띠에서 다시 열 수 있습니다
- 거절할 때 사유를 남길 수 있고, 관리자 화면에 그대로 보입니다

관리자 쪽 화면
- 승인 전에는 해당 칸이 **비활성**이고 `승인 필요` 표시가 붙습니다
- 승인되면 초록색 안내와 기한이 표시되고, 저장하면 곧바로 다시 잠깁니다
- 승인을 안 쓰고 되돌리려면 [승인 반납(다시 잠금)]
- **정보 수정 승인** 화면에서 전체 요청·응답을 봅니다 (대기 건수는 사이드바 숫자로)

> **보안 규칙에도 같은 조건이 들어 있습니다.** 화면의 잠금을 우회해도 Firestore가 거부합니다.
> 직원은 승인 상태를 스스로 `approved` 로 만들 수 없고(`pending`·`canceled`·`used`·`expired` 만 가능),
> 고객은 `status`·`respondedAt`·`expiresAt`·`rejectNote` 만 바꿀 수 있습니다.
>
> 기한(`expiresAt`)은 문자열로 저장되어 규칙에서 비교할 수 없으므로 앱이 확인합니다.
> 기한이 지난 승인으로는 화면에서 수정할 수 없지만, 규칙만 보면 `approved` 로 남아 있습니다.
> 저장을 마치면 `used` 로 바뀌어 규칙 단계에서도 잠깁니다.

> 요청을 보내려면 그 교회에 **연결된 계정**이 있어야 합니다 (`customers.userId`).
> 신청서를 통해 자동 등록된 고객은 이미 연결되어 있고, 직접 등록한 고객은
> [지원 신청] 화면에서 신청 건을 그 고객으로 연결하면 이어집니다.

## 5. Firebase 연결 (실제 운영 전환)

`assets/js/firebase-config.js` 의 값만 채우면 즉시 Firebase로 전환됩니다. 다른 코드는 고치지 않아도 됩니다.

1. [Firebase 콘솔](https://console.firebase.google.com) 에서 프로젝트 생성
2. **Authentication** → 시작하기 → `이메일/비밀번호` 사용 설정 (원하면 `Google` 도 함께)
3. **Firestore Database** → 데이터베이스 만들기 (위치: `asia-northeast3` 서울 권장)
4. **Firestore → 규칙** 탭에 규칙 전체를 붙여넣고 게시 (아래 *규칙 게시하기* 참고)
5. **프로젝트 설정 → 내 앱 → 웹(`</>`)** 추가 후, 표시되는 `firebaseConfig` 값을 `firebase-config.js` 에 붙여넣기
6. **Authentication → 설정 → 승인된 도메인** 에 배포 주소(예: `intoedu.github.io`) 추가

### 규칙 게시하기 (전체 덮어쓰기)

보안 규칙은 **부분 수정이 아니라 전체를 덮어쓰는** 방식입니다. 세 가지 방법 중 편한 것을 쓰세요.

#### 방법 1 — 관리자 화면에서 복사 (권장)

관리자 화면 → **센터 관리 → 보안 규칙** (`admin.html#rules`)

1. **[규칙 전체 복사]** 클릭
2. **[Firebase 규칙 화면 열기]** 로 콘솔 열기
3. 편집창에서 `Ctrl+A` → `Delete` → `Ctrl+V`
4. **[게시]**

이 화면에는 배포된 저장소의 `firestore.rules` 가 그대로 표시되므로 **항상 최신본**입니다.
`규칙 판` 번호가 콘솔에 게시한 것과 다르면 다시 붙여넣으면 됩니다.
[파일로 내려받기] 로 `firestore.rules` 파일을 받을 수도 있습니다.

#### 방법 2 — 명령 한 줄 (Firebase CLI)

```bash
npm run rules:login   # 처음 한 번만 (구글 로그인)
npm run rules         # firestore.rules 를 caps-4e079 에 게시
```

`firebase.json` 과 `.firebaserc` 가 저장소에 있어 프로젝트를 따로 지정하지 않아도 됩니다.

#### 방법 3 — GitHub에서 직접 복사

```
raw.githubusercontent.com/intoedu/Caps-Home-Page/claude/church-support-platform-b296qn/firestore.rules
```

### 첫 최고관리자 만들기

Firebase 연결 후 처음 회원가입한 계정은 승인 대기 상태입니다.
Firestore 콘솔에서 `users` 컬렉션의 해당 문서를 찾아 직접 바꿔주세요.

```
role: "owner"
approved: true
```

이후부터는 그 계정으로 관리자 화면에서 다른 직원을 승인할 수 있습니다.

> `firebaseConfig` 값은 공개되어도 되는 식별자입니다. 비밀 키가 아닙니다.
> 실제 보안은 `firestore.rules` 가 담당합니다 — 규칙을 반드시 게시하세요.

### 데이터 구조 (Firestore 컬렉션)

| 컬렉션 | 내용 | 공개 읽기 |
|--------|------|-----------|
| `users` | 계정, 직분, 권한, 승인 여부 | ✕ |
| `requests` | 지원 신청 (접수번호, 상태, 담당자, 메모, 할 일) | ✕ (본인 것만) |

## 6. 신청 흐름

1. 방문자가 항목 페이지에서 **[이 항목 신청하기]** → `apply.html?service=homepage` (해당 항목 자동 선택)
2. 필요한 항목을 **복수 선택** → 선택한 항목에 맞는 추가 질문이 자동으로 나타남
3. 필수값 검증 (교회명 / 담당자 / 연락처 / 소재지 / 요청 내용 / 개인정보 동의), 전화번호 자동 하이픈
4. 제출 시 **로그인/회원가입 모달** → 완료 후 이어서 자동 제출 (입력 내용 유지)
5. `CAPS-YYMMDD-XXXX` 형식 **접수번호** 발급
6. `status.html` 에서 접수번호로 조회, 로그인 시 **내 신청 내역** 목록 표시
7. 관리자 **지원 신청** 화면에서 **[고객으로 연결하기]** 를 누르면 교회명이 같은 고객에 연결되고,
   없으면 고객을 새로 만듭니다 → 이후 구독·정산에서 같은 교회로 묶여 보입니다

> 고객 연결을 신청 시점에 자동으로 하지 않는 이유: 그러려면 신청자가 **다른 교회의 고객 목록까지 읽을 수 있어야** 합니다.
> 개인정보 보호를 위해 조회 권한이 있는 관리자 화면에서 처리합니다.

## 10. 기술 사항

- 프레임워크·빌드 도구 없음 — 순수 HTML / CSS / 바닐라 JS (생성 스크립트만 Node 사용)

- 반응형: 1180 / 960 / 900 / 820 / 680px 구간. 관리자 화면도 모바일 대응
- 접근성: 본문 바로가기, 키보드 조작, `aria-*`, 포커스 표시, `prefers-reduced-motion`
- 인쇄 스타일 포함

- CAPS 신청서에서 두 항목이 체크박스가 아닌 링크로 표시되고 선택 항목은 6개
- 내 작업에서 마감일 저장 → D-2 / D+3 배지 계산, 직원별 업무량 집계
- 로그인·회원가입 양쪽 탭의 구글 버튼 노출
- [보안 규칙] 화면의 규칙 전체 노출과 클립보드 복사 결과가 원본과 일치
- 회원가입에서 교회명·직분 미입력 시 차단, 비밀번호 불일치 차단
- 연락처에 15자를 입력해도 숫자 11자리로 잘리고 `010-1234-5678` 로 포맷
- 고객 계정 탭에 교회·직분·생년월일·연락처 표시, ⋯ 메뉴로 직원 전환
- 교회·직분·연락처가 빈 계정으로 로그인하면 공개 페이지 · 신청 폼 · 직원 포털 ·
  관리자 화면 **네 곳 모두** [추가 정보 입력] 화면으로 차단, Esc·배경 클릭으로 닫히지 않음
- 저장하면 Firestore·헤더에 즉시 반영되고 원래 흐름(관리자 화면 진입)으로 이어짐,
  다음 방문 때는 다시 묻지 않음
- 구글 가입 버튼을 빈 칸 상태로 눌러도 사전 입력을 요구하지 않음
- 홈페이지 회원가입 창과 직원 계정 신청 창 **양쪽 모두** 구글 버튼이 폼 맨 위에 위치
- 승인 없이 고객 교회 정보 칸이 비활성이고 `승인 필요` 표시가 붙음, 내부 메모는 그대로 저장됨
- [정보 수정 요청 보내기] → 문서 아이디가 고객 아이디로 저장되고 승인 계정·항목·사유가 정확히 기록됨
- 고객 계정으로 로그인하면 안내 띠와 승인 창이 뜨고, Esc 로 닫아도 띠에서 다시 열림
- 승인 → 관리자 화면에서 칸이 열리고 목록에 [수정 가능] 표시, 저장하면 `used` 로 재잠금
- 거절 → 사유가 저장되고 관리자 화면 잠금 안내에 그대로 표시, 칸은 계속 잠김
- 연결된 계정이 없는 고객에게는 요청 버튼 대신 안내가 표시됨
- `firestore.rules` 에 승인 검사, 고객이 바꿀 수 있는 항목 제한, 직원의 자가 승인 차단이 모두 포함됨
